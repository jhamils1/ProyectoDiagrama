# Panel lateral y archivos compartidos

El asistente compartido se abre en un panel a la derecha, sustituyendo temporalmente el inspector y dejando el lienzo utilizable. Usa fondo oscuro, mensajes morados y transición deslizante de entrada y salida (280 ms), desactivada si el usuario prefiere movimiento reducido. El botón Asistente IA compartido alterna la visibilidad del panel sin descartar el borrador ni detener una consulta en curso. En pantallas estrechas el panel se superpone parcialmente al lienzo.

El panel comienza a la altura de la barra de acciones; en escritorio esta queda a su izquierda para mantener los botones accesibles y ganar altura en el chat. El control junto a cerrar amplía el asistente a toda la ventana y permite volver al panel anterior. En ese modo el contenido mantiene un ancho máximo legible y Escape restaura el tamaño. El borrador se conserva al cambiar de tamaño.

Actualización del 6 de noviembre: por petición del usuario se retiró la pestaña Archivos y no se permite subir archivos. El backend rechaza las cargas con 403 mediante `modela.shared-files.uploads-enabled: false`, incluso desde clientes anteriores. El código de archivos y los datos existentes se conservan para una etapa posterior. Solo el perfil de pruebas habilita las cargas para seguir verificando la funcionalidad pendiente.

El borde izquierdo del panel permite redimensionarlo con ratón o puntero táctil. Arrastrar a la izquierda amplía el asistente; a la derecha lo reduce. Doble clic restablece 380 px. El separador admite teclado (flechas, Mayús para pasos mayores, Inicio/Fin) y Escape cancela un arrastre. Los límites se recalculan al cambiar de ventana, dejando al menos 320 px para el lienzo en escritorio cuando el espacio disponible lo permite. El borrador y el motor permanecen montados durante el ajuste; al cerrar y volver a abrir se usa el ancho inicial.

Los archivos pertenecen al proyecto y son accesibles a sus participantes autenticados, incluidos usuarios de consulta. Cualquier participante puede compartir o descargar; solo quien subió un archivo o un administrador puede eliminarlo. La API comprueba acceso en cada operación. El almacenamiento es PostgreSQL (`bytea`), no el navegador ni S3. La migración V16 se aplicó en `modela_test` y se aplica a la base local de desarrollo al reiniciar el backend; no se aplicó en AWS.

Límites iniciales: hasta 5 MiB por archivo, 50 MiB y 100 archivos por proyecto. Extensiones permitidas: TXT, PDF, PNG, JPG/JPEG, XML, XMI, JSON, CSV, DOCX y XLSX. Se comprueba la extensión, no el contenido interno. Las descargas se sirven como adjuntos y sin caché. El ID de carga permite reintentar una respuesta incierta sin duplicar; el tamaño agregado se comprueba con bloqueo del proyecto. No es un mecanismo para distribuir el modelo de IA, cuya distribución por USB sigue pospuesta.

Pruebas tras el ajuste visual y bloqueo: 174 pruebas de backend aprobadas con PostgreSQL de prueba, incluida la denegación de cargas deshabilitadas sin llamar al servicio de almacenamiento. Build web y lint sin errores, con tres advertencias previas. Los 19 casos E2E del panel/asistente pasaron con API y Worker simulados; incluyen entrada animada, movimiento reducido, pantalla estrecha, ausencia de carga de archivos y lienzo interactivo. Se inspeccionó `.qa/shared-assistant-dark.png`. No se ha probado con usuarios reales ni se ha publicado en la nube.
